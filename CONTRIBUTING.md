# Maintenance rules

1. Read the brand workspace's `BRAND_STATUS.md`, `BRAND_IDENTITY.md` and `SOURCES.md` first.
2. Confirm a non-main branch before editing. Preserve unrelated unfinished work; never bulk-stage a dirty workspace.
3. Follow current route/component imports, not archived design instructions. Keep the lens interaction and existing approved media intact.
4. Edit the actual owner: metadata/navigation in `data/`, route copy in `src/app/`, section copy in `src/components/`. Do not claim all content is JSON-driven.
5. Use the shared cream/navy/teal system in `unified.css`. No competing global override layer.
6. Next `Link` hrefs omit `/jackieng-profile`; raw public-media URLs include it exactly once.
7. Distinguish published results, personal contributions, research directions and synthetic/public demos. No invented data, inflated participation titles or unverified delivery metrics.
8. Never put PDB/mmCIF files in `public/`. Use approved rendered videos only. Do not select new photos without visual verification.
9. Run lint, build, inference checks and export checks. Test desktop/mobile layout, navigation, contact anchors and lens controls in a browser.
10. Merge to main/push only after checks; verify the exact Actions SHA and live content. Update brand status to distinguish local, pushed and live.

Historical source and documents are in `docs/archive/` for recovery, not reuse as current instructions.
